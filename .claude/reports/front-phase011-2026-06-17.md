## 1. Résumé

Implémentation complète de la phase 11 (archive-document-service) du frontend VisioMath.
La phase expose l'historique pédagogique chronologique des élèves avec gestion fine des droits
selon le rôle (parent financeur exclus du carnet personnel, résumés de cours permanents).

## 6. Limites restantes

| Limite | Raison |
|---|---|
| Pas d'UI de création de lien d'archive (`POST /archive-links`) | La spec phase 11 ne prévoit pas de formulaire de création côté élève — réservé aux formateurs/RP dans un écran admin ultérieur |
| Les items `content_catalog` sont des placeholders visuels | Les contenus du catalogue pédagogique (phase 3) n'existent pas encore — conformément à `allowedMocksUntilDependenciesExist` de la spec |
| Le téléchargement blob suppose que le filename est dérivé de l'id | Le backend devrait renvoyer un `Content-Disposition` header — le front utilise `archive-{id}` comme fallback |

---

## 7. Décisions techniques

- **Deux appels parallèles** (`fetchPedagogicalArchives` + `fetchArchiveTimeline`) via `Promise.all` pour minimiser la latence d'affichage initial.
- **Onglets Timeline / Résumés de cours** : séparation claire entre vue chronologique générale et vue filtrée dédiée aux résumés permanents (VID-AC-002).
- **Restriction parent financeur gérée côté UI** : le backend renvoie `isAccessibleToFinanceOwner: false` pour les `notebook_entry` ; l'UI masque les actions et affiche un message explicatif — pas de faux 403.
- **Lien "Archives" masqué pour TI et AF** : ces rôles n'ont pas vocation à consulter les archives pédagogiques élève depuis la navigation globale (accès via URL directe `/archives/:studentId` possible pour usage interne).
