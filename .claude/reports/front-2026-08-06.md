# Rapport front — 2026-08-06

## Sujet
Ajout de deux boutons de navigation croisée entre les flux de rattachement parent↔élève
existants et les pages d'inscription, sans nouveau contrat backend :

- Côté élève : bouton "Créer un nouveau compte parent" (ouvre `/register/parent` dans un
  nouvel onglet).
- Côté parent : bouton "Créer un compte élève" (ouvre `/register/student` dans un nouvel
  onglet).

Fonctionnalité purement front, aucun appel API ajouté ou modifié — uniquement de la
navigation (`react-router-dom` `<Link target="_blank" rel="noopener noreferrer">`).

## Localisation des UI existantes (avant modification)

1. **Côté élève — demande de liaison à un parent financeur** :
   `apps/web/src/components/profile/InviteParentForm.tsx`, monté par
   `apps/web/src/components/profile/ParentFinanceurSection.tsx`, elle-même affichée dans
   l'onglet "Parents financeurs" de `ProfilePage` (visible pour le rôle `eleve`, cf. règle
   "Page Profil — structure en onglets"). Utilise
   `createStudentInitiatedRequest` (`POST /parent-link-requests/student-initiated`).

2. **Côté parent — liaison à un élève existant** — deux interfaces distinctes trouvées,
   toutes deux traitées :
   - `apps/web/src/components/profile/InviteStudentForm.tsx`, monté par
     `apps/web/src/components/profile/LinkedStudentsSection.tsx`, affiché dans l'onglet
     "Mes élèves / enfants" de `ProfilePage` (rôle `parent_financeur`). Utilise
     `createParentLinkRequest` (`POST /parent-link-requests`).
   - `apps/web/src/pages/ParentLinkRequestPage.tsx`, page standalone routée sur
     `/parent-link-requests`, accessible via la navigation latérale du rôle
     `parent_financeur` (entrée "Demande de rattachement" dans
     `navigation/navigationConfig.ts`). Même appel API que ci-dessus.

   Ces deux UI parent réalisent la même action métier (créer une demande de rattachement
   vers un élève par identifiant de connexion) mais sont deux points d'entrée UX distincts
   et navigables indépendamment — le bouton a donc été ajouté aux deux pour cohérence,
   plutôt que de n'en traiter qu'une seule.

3. Une branche `wip/discarded-combined-parent-student-registration` existe en local avec une
   tentative abandonnée de formulaire combiné (case à cocher dans le formulaire d'inscription
   parent). Consultée uniquement pour confirmer l'emplacement des UI ci-dessus ; son approche
   (formulaire combiné) n'a pas été reprise, conformément à la consigne.

## Modifications appliquées

- `apps/web/src/components/profile/InviteParentForm.tsx` : bouton secondaire
  "Créer un nouveau compte parent" à côté du bouton "Envoyer une invitation", lien
  `react-router-dom` vers `/register/parent`, `target="_blank"`, `rel="noopener noreferrer"`.
- `apps/web/src/components/profile/InviteStudentForm.tsx` : bouton secondaire
  "Créer un compte élève" à côté du bouton "Envoyer une invitation", lien vers
  `/register/student`, mêmes attributs de nouvel onglet.
- `apps/web/src/pages/ParentLinkRequestPage.tsx` : même bouton "Créer un compte élève" à
  côté du bouton "Envoyer la demande" du formulaire standalone `/parent-link-requests`.

Style : classes Tailwind cohérentes avec le design system existant du dossier
(`border border-indigo-300 text-indigo-700 hover:bg-indigo-50`), à côté du bouton primaire
`bg-indigo-600` déjà présent dans chacun des trois formulaires. Aucun nouveau composant UI
générique introduit — motif volontairement minimal et local à ces trois fichiers.

Aucune modification des routes API existantes ; `/register/student` et `/register/parent`
sont des routes de navigation React déjà déclarées dans `App.tsx` (composants
`StudentRegistrationPage` / `ParentRegistrationPage`), confirmées avant implémentation.
