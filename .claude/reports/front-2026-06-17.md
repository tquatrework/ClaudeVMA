## Décisions techniques

- **Modules API séparés** : `finance.ts` et `legal.ts` suivent le même pattern que `communication.ts`
- **Mocks dans les tests** : `vi.mock('../../src/api/legal')` mocke le module entier pour tester la logique de la page sans appels réseau
- **Pré-remplissage signerName** : le champ est prérempli avec `user.email` ; les tests nettoient l'input avant de taper (`userEvent.clear`)
- **Copie sécurisée** : retourne un `Blob` avec `responseType: 'blob'` — téléchargement via URL.createObjectURL
- **Route /legal/templates doit être avant /legal/:ownerId** dans App.tsx pour éviter le conflit de paramètre URL

## Points en suspens

- `GET /legal-templates` (chargement de la liste) n'est pas documenté dans routes.md — la page l'appelle via `apiClient.get('/legal-templates')` en faisant un best-guess sur le contrat backend. À confirmer avec l'équipe backend.
- `GET /financial-settings/rewards` (lecture des paramètres actuels) idem — non documenté, les paramètres affichés sont donc initialisés en local (pointsPerEuro = 1 par défaut).
- Le teacher-payment-requests backend n'est pas documenté dans routes.md au moment de la rédaction — implémentation basée sur les patterns existants du projet.
