# Rapport frontend VisioMath — 2026-06-13

## Incohérences fonctionnelles détectées

### 1. Route `/video/rooms/:roomId/join` — méthode GET vs POST
- **Spec front.md** : `GET /video/rooms/:roomId/join` pour obtenir le lien d'accès
- **routes.md** : `GET /video/rooms/:id/join` — cohérent
- **Code précédent** : utilisait `POST` sur la même URL — **corrigé** : VideoPage utilise maintenant `GET`

### 2. Orchestration `/orchestration/commands` — chemin différent dans routes.md vs front.md
- **front.md** déclare `POST /orchestration/commands` comme écran `AdminActivityPage`
- **routes.md** déclare `POST /commands` (sans préfixe `/orchestration`) via le gateway `orchestration-service`
- **Décision prise** : utilisation de `/orchestration/commands` (préfixe nginx `/api/v1/orchestration`) conformément à la gateway nginx qui préfixe les routes avec `/orchestration/`

### 3. `DashboardPage` — notifications : réponse paginée ou tableau direct
- **front.md** (FRONT-PR-004) : les réponses paginées ont la forme `{data, meta}`, les tableaux directs restent des tableaux
- **DashboardPage précédente** ne traitait que la forme `{data: [...]}`, ignorant un tableau direct
- **Corrigé** : le composant accepte maintenant les deux formes (`Notification[] | {data: Notification[]}`)

### 4. Question ouverte FRONT-Q-001 non tranchée
- La spec pose la question : faut-il conserver `/calendar` comme route principale ou migrer vers `/activities` ?
- **Décision conservatrice adoptée** : on maintient `/calendar` comme route principale des séances (conformément à routes.md). Les URLs `/activities/:activityId` restent pour le détail.

## Blocages

Aucun blocage bloquant. Quelques points à surveiller lors de l'intégration :

1. La réponse de `GET /notifications` peut être soit un tableau, soit `{data, meta}` — le frontend gère les deux formes mais une normalisation backend serait préférable.
2. `GET /orchestration/workflows` renvoie les **types** de workflow disponibles selon routes.md, pas les instances actives — il n'existe pas d'endpoint listé pour les instances actives. L'onglet "Instances actives" reste vide tant que l'API backend ne propose pas cet endpoint.
3. Le formulaire "proposer un formateur" utilise un UUID saisi manuellement car il n'existe pas d'endpoint de recherche de formateurs en phase 1.
